Parser faktur, który uczy się od operatora

Każdy dostawca przysyła faktury w innym formacie. Zamiast pisać integrację dla każdego z nich, system czyta dowolny plik strukturalny (XML, JSON, CSV). Przy pierwszej fakturze nowego dostawcy pyta o to, czego nie rozumie, i zapamiętuje odpowiedzi jako szablon dostawcy. Kolejne faktury czyta już sam.

Jak to działa

  1. Odczyt — plik zamieniany jest na drzewo ścieżek (np. Faktura/Naglowek/DostawcaNIP), niezależnie od formatu. Pliki XML z DOCTYPE/ENTITY są odrzucane (bezpieczeństwo).
  2. Rozpoznanie dostawcy — po NIP/VAT; gdy go nie ma — po „odcisku” struktury pliku.
  3. Szablon — reguły: pole docelowe ← ścieżka w pliku → transformacje (np. usuń „%”, wytnij partię z kodu GS1-128). Dla nowego dostawcy system proponuje reguły sam, na podstawie słownika synonimów (PL/EN/KSeF/UBL) i typów wartości.
  4. Słowniki — jednostki miary (pcs → szt), przeliczniki (1 karton = 12 szt), przypisanie towarów dostawcy do naszych indeksów.
  5. Walidacja — ilość × cena = wartość, suma pozycji = suma faktury, netto + VAT = brutto, wykrywanie duplikatów.
  6. Negocjacja — gdy czegoś brakuje, faktura trafia do kolejki „do wyjaśnienia”. Operator wybiera podpowiedź i decyduje: tylko ta faktura albo zapamiętaj. Zapamiętanie tworzy nową wersję szablonu.
  7. Wynik — znormalizowany JSON dostępny przez REST API dla innych systemów.

Scenariusz demo (5 minut)

  1. Zaloguj się i wczytaj alfa-1.xml — faktura trafi do kolejki z problemami.
  2. Rozwiąż problemy od góry: utwórz dostawcę, ustaw domyślną walutę, wskaż, że pcs to szt, przypisz „Masę marcepanową” do towaru z kartoteki.
  3. Wczytaj alfa-2.xml — zostanie zatwierdzona automatycznie, bez pytań.
  4. Spróbuj innych formatów: KSeF, UBL, CSV, JSON — ten sam mechanizm.
  5. Zajrzyj do Szablony → wersje i różnice, oraz do Edytora mapowań.
